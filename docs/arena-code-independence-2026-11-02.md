# Arena Code 独立化记录 · 2026-11-02

## 结论

Arena Code 已从“外部终端工程 + 本地补丁”改为仓库内独立实现：

- 源码在 `arena-code/`，只用 Node.js 标准库，无第三方运行时依赖；
- 删除旧补丁文件，不再需要克隆外部工程、应用补丁或构建外部工作区；
- Windows 启动器按脚本位置直接运行 `arena-code/bin/arena-code.js`；
- 配置仍放在 `~/.arena/settings.json`，并兼容已有的 provider 风格字段；
- 仓库工作树内已无已移除品牌的中英文名称命中。

## 为什么重写一个小终端，而不是搬运整套外部工程

旧终端工程当前上游约有 13,779 个跟踪文件；其中十万行量级的内容带有原品牌或其包名、目录、环境变量、快照与模型提供方标识。若整仓复制再机械替换，会同时带来：

1. 一个无法审查的巨大补丁（十万行量级改名）；
2. 包作用域、构建脚本、测试快照、兼容目录和遥测/更新逻辑一起漂移；
3. 后续每个安全修复都要在改名后的分叉里重复解冲突；
4. 仓库体积、补丁归档和评审成本显著增加。

而 Arena Bridge 的分工本来就很明确：Arena 页面负责系统提示词、仓库上下文、Agent 工具和实际执行；终端只负责输入、流式显示、模式与会话切换，以及 `/repo`、`/upload`、`/vote` 等桥命令。将这一小层独立实现，能用可审查的约千行代码覆盖实际用到的能力，并把维护面收回到本项目。

## 已保留的能力

- OpenAI 兼容流式/非流式对话；
- `arena-agent`、`arena-direct` 及 battle / side 模式；
- 本地多轮记录与按会话名保存；
- `/status`、`/models`、`/model`、`/mode`、`/session`、`/new`；
- `/repo` 列表与切换；
- `/upload` 带空格路径（用引号）；
- `/vote` 投票与模型揭晓；
- `ARB_TOKEN` / `ARENA_API_KEY` Bearer 鉴权（旧命令实现缺失的一环已补齐）；
- 非交互 stdout/stderr 分离：正文走 stdout，思考与工具行走 stderr；
- 生成时 Ctrl-C 只中止当前请求。

## 有意不保留的能力

独立终端不再内置另一套通用 Agent 运行时，例如本地工具执行、文件编辑代理、扩展系统、MCP 主机、子代理编排或独立模型提供方管理。本项目的设计前提就是“终端只是键盘和显示器”，这些能力若重新引入，反而会与 Arena 页面自己的提示词、连接器和工具状态冲突。

若未来需要这些能力，应优先扩展 Arena Bridge 的协议，而不是把第二个执行主体塞回终端。

## 迁移

1. 保留现有 `~/.arena/settings.json`；
2. 停用旧的补丁构建目录；
3. 在仓库根目录运行 `npm run code`，或在 Windows 运行 `cli-windows\arena.cmd`；
4. 如启动器被单独复制到 PATH，可设置 `ARENA_CODE_BIN` 指向 `arena-code\bin\arena-code.js`。

## 验证标准

- `npm test` 全部通过；
- `arena-code --help` 与 `--version` 可运行；
- 对模拟桥验证 `/status`、流式与非流式问答、会话落盘、`/repo`、`/vote`；
- 用伪终端验证交互模式切换与退出；
- 全仓搜索已移除品牌的中英文名称无命中（Git 历史不在本次改写范围内）。
